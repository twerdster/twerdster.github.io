# Student Project Repositories

Historical Technion student projects supervised by Aaron Wetzler. Each project has a separate repository so its original authors can contribute updates or request corrections or removal.

Sixteen repositories contain reviewed historical source or a pinned public upstream, including the newly identified TermiNet. Smartphone Game separately links externally hosted source. Recovered snapshots may be partial; new ports, illustrative reconstructions and recorded-output viewers are labeled separately in each repository. Browser demos do not establish that an original mobile/VR application builds or that its historical results were reproduced. GrayOwl remains documentation-only, with its source withdrawn.

The current directory contains 26 projects. Detailed recovery, installation, conversion and validation records live in the linked repositories. Private submission archives, signing material, SDK keys and personal records are not published.

## Source and Attribution

Public original code is pinned as a Git submodule in OpenFusion, HeartBeat, Freehand Voxel Carving, Predator for iOS and iPhone Stereo Reconstruction. Clone those repositories with `--recurse-submodules`. Other recovered code is stored under `source/`; the new recovery imports use `source/original/`. Separately labeled modern implementations, when present, live under `updated/` and do not replace the historical snapshots. Original student credits, existing notices and third-party terms are retained; this directory does not assign a blanket code license.

Privately recovered SDK binaries, signing material, private deployment values, personal records and raw submission archives are not published. Two QRoom database configuration files use environment variables. One Mobile Point Fusion comment path is also redacted. GrayOwl source and updated code are no longer published. Per-repository provenance manifests distinguish unchanged originals from sanitized files. The unmodified raw originals remain private. Reports and slides are linked separately from source availability.

The current multi-view iPhone slides have a database screenshot removed from slide 7 to protect application login details; the original remains in historical Git copies. QRoom's archived PHP backend has confirmed security vulnerabilities and must not be deployed. Pinned public upstreams require separate credential and vendor-license review before reuse.

The [homepage](https://twerdster.github.io/#projects) links project-specific code, reports, posters, demonstrations and original laboratory pages where available. The machine-readable [site index](data/site-content.json) records `repository`, `source_status`, `resources`, and pinned upstream revisions where applicable.

## Puppify browser implementation (2026-11-15)

Puppify now has a [browser app](https://twerdster.github.io/planar-marionettes/), [new source](https://github.com/twerdster/planar-marionettes/tree/main/updated/browser), [guide](https://github.com/twerdster/planar-marionettes/blob/main/updated/README.md) and [validation record](https://github.com/twerdster/planar-marionettes/blob/main/updated/browser/docs/VALIDATION.md). Aaron Wetzler wrote this new TypeScript/MediaPipe/Canvas 2D implementation from the report's photograph-to-puppet idea. It provides photo cutouts, editable joints and video-driven posing, using geometric body-part assignment from a whole-person mask. It does not run the unavailable original Caffe/FashionPose, scribble/segmentation or D3 code. Thirteen geometry/data checks cover the rig, mask handling and symmetric/asymmetric motion mirroring, not model accuracy. Crossed limbs, occlusions, fixed layer order and missing texture remain limitations. The original report, lab figure and student/supervisor attribution are preserved. Historical source_files stays zero and the fifteen historical source-bearing/pinned repositories remain fifteen.

The browser record contains 16 passing cases: eight user flows, each run in Chrome 157 at desktop and 390-pixel phone/touch-emulated viewports on macOS with CPU inference. Real prerecorded photo/video from one subject/scene and procedural negative controls passed through the actual model; no fake landmark or mask results were supplied. The flows include handling an injected model-asset HTTP 503 and successfully retrying actual inference without reloading the page. Zero external requests or uncaught errors were observed in those contexts. This is not physical-phone, Safari/Firefox, GPU-execution or accuracy validation.

## CutOut browser interface, 2026-11-16

The [CutOut browser app](https://twerdster.github.io/cutout-android/) accepts an image and foreground/background scribbles, runs the shared updated C++ segmentation core as WebAssembly, and exports PNG masks and cutouts. It processes pixels locally in a Web Worker, using the C++ core rather than the separate Python Fast Marching exercise. The [browser guide](https://github.com/twerdster/cutout-android/blob/main/updated/browser/README.md) covers use and local builds; the [validation record](https://github.com/twerdster/cutout-android/blob/main/updated/browser/VALIDATION.json) separates operator comparisons from browser interaction checks.

Sixteen native/WebAssembly comparisons cover eight operator combinations on a procedural ellipse and one coffee photograph; binary-mask and alpha bytes match on those inputs. This is implementation consistency, not a segmentation-accuracy benchmark. The original Android source, historical-interface limitations and third-party terms remain separate. No new project or source-bearing repository is counted.

Chrome 157 on macOS 15.1.1 completed eight coffee-image operator combinations and checks for local image upload, pointer strokes, undo/clear, stale-result handling, cancellation recovery and both PNG downloads. Layouts at 390/1440 pixels had no overflow, external requests or uncaught page errors. A separate Chrome UI-driven interaction check observed one FIGTree/pixel/hard result. These checks do not validate physical Android/iOS browsers or Safari/Firefox.

For the sixteen core comparisons, WebAssembly ran in Node.js 23.11.0 on macOS 15.1.1 arm64, outside the browser’s image decoder and Canvas stroke rasterizer. Six expected invalid-input cases were also checked. Aaron Wetzler added the browser interface and Worker bridge around the shared updated core.

The browser app source is published at [`6edd6e6`](https://github.com/twerdster/cutout-android/commit/6edd6e61fddaa76a0901e61cebcd8fc0ec20e5a1). [GitHub Actions run 43768661137](https://github.com/twerdster/cutout-android/actions/runs/43768661137) rebuilt the package, passed its native/WebAssembly and browser checks, and deployed GitHub Pages. The CI comparison uses native OpenCV 4.6.0 and WebAssembly OpenCV 4.12.0; it is separate from the same-version local byte comparison. Generated build-path diagnostics are normalized, and packaging rejects recorded private path prefixes before deployment.
