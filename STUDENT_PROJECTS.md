# Student Project Repositories

Historical Technion student projects supervised by Aaron Wetzler. Each project has a separate repository so its original authors can contribute updates or request corrections or removal.

Fifteen repositories contain reviewed historical source or a pinned public upstream. Separately, Smartphone Game links source hosted on Idan Banani's GitHub account; it is not imported here and its build is unverified. GrayOwl retains project information and public resource links; its source code and updated notebook have been withdrawn. CutOut's original Android Java/JNI C++ source was recovered on 2026-11-13; its historical Eclipse interface remains unbuilt. The separately updated implementation now provides Android and iOS interfaces, a local drawing interface, and a native CLI with recorded macOS and Linux checks. Its separate related algorithm prototype still has unverified authorship. Three repositories contain documents without verified app source, two have introductory READMEs, and RobotRun has a separately implemented browser game with no recovered original Unity source. Historical snapshots may be partial and are not complete modern application releases. Four repositories also have separately labeled Python components with recorded unit tests and notebooks executed with Jupyter on macOS. Colab links open the notebooks; follow the setup instructions in each component guide before running them. These exercises do not replace the original applications. Consult each README for missing dependencies and the exact recovery status; a source link does not imply a complete, runnable application.

Nine projects have a **New!** link to their separately labeled updated section.
Each guide begins with a short account of the changes, then links setup, results
and limitations. The historical recovery records and existing platform evidence
remain separate from that navigation.

## Source and Attribution

Public original code is pinned as a Git submodule in OpenFusion, HeartBeat, Freehand Voxel Carving, Predator for iOS and iPhone Stereo Reconstruction. Clone those repositories with `--recurse-submodules`. Other recovered code is stored under `source/`; the new recovery imports use `source/original/`. Separately labeled modern implementations, when present, live under `updated/` and do not replace the historical snapshots. Original student credits, existing notices and third-party terms are retained; this directory does not assign a blanket code license.

Privately recovered SDK binaries, signing material, private deployment values, personal records and raw submission archives are not published. Two QRoom database configuration files use environment variables. One Mobile Point Fusion comment path is also redacted. GrayOwl source and updated code are no longer published. Per-repository provenance manifests distinguish unchanged originals from sanitized files. The unmodified raw originals remain private. Reports and slides are linked separately from source availability.

The current multi-view iPhone slides have a database screenshot removed from slide 7 to protect application login details; the original remains in historical Git copies. QRoom's archived PHP backend has confirmed security vulnerabilities and must not be deployed. Pinned public upstreams require separate credential and vendor-license review before reuse.

The [homepage](https://twerdster.github.io/#projects) links project-specific code, reports, posters, demonstrations and original laboratory pages where available. The machine-readable [site index](data/site-content.json) records `repository`, `source_status`, `resources`, and pinned upstream revisions where applicable.

The 2026-11-13 author follow-up added Smartphone Game’s source link, CamPong’s additional original documents and supplied video/profile links, and the original RiftFusion presentation with its authors’ supplied profile links. These resources do not establish a current application build. Individual correspondence permissions are described in the affected repository READMEs without publishing the messages or assigning a new blanket license.

Elad Richardson's later 2026-11-13 contribution adds [CutOut's original Android source](https://github.com/twerdster/cutout-android/tree/main/source/original/android-app). Its [source/build notes](https://github.com/twerdster/cutout-android/blob/main/docs/original-android.md) describe the recovered Java interface, JNI C++ implementation and missing dependencies. That recovery did not validate the historical Android interface or establish the authorship of the separate related prototype. The earlier Python component tests remain independent of the native restoration.

The updated CutOut implementation provides a [native CLI](https://github.com/twerdster/cutout-android/blob/main/updated/native/README.md), [local drawing interface](https://github.com/twerdster/cutout-android/blob/main/updated/desktop/README.md), [Android interface](https://github.com/twerdster/cutout-android/blob/main/updated/android/README.md) and [iOS interface](https://github.com/twerdster/cutout-android/blob/main/updated/ios/README.md) around the recovered segmentation operators. [Linux native/CLI validation](https://github.com/twerdster/cutout-android/blob/main/updated/validation/LINUX_VALIDATION.json) and the platform records describe completed execution; mobile fixture runs remain separate from interface tests. The original 319 Android files remain unchanged. These checks do not establish photographic accuracy, compatibility with untested OS/device combinations or equivalence to the historical Android interface.

Sa'ar Zehavi supplied [unfinished April 2013 hand-tracking slides](https://github.com/twerdster/hand-tracking-pmd/blob/main/docs/real-time-hand-tracking-draft-2013.pptx). Supplied on 2026-11-13, the slides include an abandoned first-order approximation step and placeholder illustrations; they do not replace the June report or recovered source. No additional code or execution result arrived with the slides. Amit Bekerman's later RobotRun reply approves keeping the project on the website with Amit credited by name; the repository records that response separately from Hadar Reuveny's. RobotRun's Unity source remains unavailable. Vlad Ostrovski confirmed RiftFusion's existing historical video link, without supplying application source.

On 2026-11-13, RobotRun gained a [new browser implementation](https://github.com/twerdster/robotrun-game/tree/main/updated/browser) with [setup instructions](https://github.com/twerdster/robotrun-game/blob/main/updated/browser/README.md) and a [validation record](https://github.com/twerdster/robotrun-game/blob/main/updated/browser/docs/VALIDATION.md). TypeScript, Three.js and MediaPipe provide a three-lane, 1,000-metre course with webcam, keyboard and touch controls. Coins add ten points; fire reverses controls for ten seconds. Hand Landmarker with its GPU delegate was checked in a Chrome 157 production preview using a prerecorded Google hand test photo, spatially shifted across video frames. Camera lifecycle checks used an emulated stream, with synthetic camera-ended and visibility events. No live-person camera session or mobile-device runtime was tested, and the original Unity/Intel-camera implementation remains unbuilt. The archived student screenshot and individual author-response scopes are unchanged; the new source does not increase the historical-source repository count.
